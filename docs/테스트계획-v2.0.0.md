# PPT Slider 2.0.0 테스트 계획

| 항목 | 내용 |
|---|---|
| 대상 | PPT Slider 2.0.0 (SOLID 리팩토링 + PowerPoint식 편집 기능) |
| 기준 커밋 | `ecdfc64` (편집 기능) 위의 리팩토링 작업본 |
| 작성일 | 2026-11-02 |
| 결과 보고 | [테스트결과-v2.0.0.md](테스트결과-v2.0.0.md) |

## 1. 목적

1. 리팩토링 뒤에도 앱의 동작이 리팩토링 전과 같은지 확인합니다.
   - 문서 모델(Deck)을 책임별 클래스로 나눴습니다.
   - MainWindow의 편집 로직을 `IEditorHost` 뒤의 부품으로 옮겼습니다.
   - 명령 실행을 레지스트리(명령 이름 → 동작의 표)로 바꿨습니다.
   - 렌더러의 도우미를 분리했습니다.
2. 2.0.0으로 배포할 수 있는지 확인합니다. Release 빌드, MSIX 패키지, 버전 표기를 봅니다.

## 3. 환경과 도구

- Windows 11 Pro, .NET 10 SDK, DocumentFormat.OpenXml 3.5.1
- **자동 테스트**: `PptSlider.exe --selftest <deck.pptx> <outDir>`
  - 각 검사가 `PASS`/`FAIL`로 `selftest.txt`에 기록되고, 렌더링 결과 PNG가 함께 저장됩니다.
  - 마우스·키보드 검사는 실제 이벤트 처리기가 쓰는 코드 경로(`StageInteraction`, `HandleKey`)를 좌표와 수정 키로 직접 실행합니다.
- **화면 캡처**: `PptSlider.exe --screenshots <deck.pptx> <outDir> ko`
  - 실제 창을 띄워 편집 화면, 판서, 쇼, 발표자 보기를 캡처합니다.
- **OOXML 검증**: `OpenXmlValidator(Office2019)`(자체 테스트 안에서 실행)
- **테스트 문서**: 4:3 테스트 덱(`test.pptx`). 텍스트, 표, 그림, SmartArt, 노트가 들어 있습니다.

## 4. 진입·종료 조건

**진입 조건**
- [ ] 리팩토링 작업본이 Debug로 경고·오류 없이 빌드된다.

**종료 조건(합격)**
- [ ] 아래 체크리스트 항목이 모두 충족된다.
- [ ] 자체 테스트 `FAIL` 0건.
- [ ] 2.0.0 Release 빌드와 MSIX 패키지가 만들어진다.

결함이 나오면 고친 뒤 해당 분류 전체를 다시 수행하고, 결과 보고서에 기록합니다.

## 5. 테스트 항목과 충족 조건

"방법"의 **자동**은 자체 테스트에서 해당 접두어(예: `mouse:`)로 시작하는 검사를 뜻합니다. **확인**은 결과물(이미지·파일·코드)을 직접 검사하는 것을 뜻합니다.

### T1. 빌드와 정적 검사

| ID | 테스트 내용 | 충족 조건 | 방법 |
|---|---|---|---|
| T1-1 | Debug 빌드 | 오류 0, 경고 0 | `dotnet build` |
| T1-2 | Release 빌드(2.0.0) | 오류 0, 경고 0. 출력 DLL의 파일 버전이 2.0.0 | `dotnet build -c Release` |
| T1-3 | 3개 언어 문자열 | 소스가 쓰는 키가 모두 한·일·영으로 정의돼 있음 | 자동 `loc:` |
| T1-4 | 기본 단축키 중복 | 한 키가 두 명령에 겹치지 않음 | 자동 `keys: no default key…` |

### T2. 리팩토링 구조(SOLID)

| ID | 테스트 내용 | 충족 조건 | 방법 |
|---|---|---|---|
| T2-1 | SRP: Deck | `Deck`에는 문서 입출력, 슬라이드 목록, 편집 기록(History)만 남음. 도형·표·텍스트·클립보드·서식 편집은 각자의 클래스에 있음 | 확인(코드) |
| T2-2 | SRP: MainWindow | 편집 로직(선택, 드래그, 텍스트 편집기, 개체·텍스트·표·삽입·클립보드·서식 복사 명령)이 `src/Editing`의 클래스에 있음. MainWindow에는 조립, XAML 처리기, 메뉴 UI만 남음 | 확인(코드) |
| T2-3 | DIP | `src/Editing`의 클래스는 `MainWindow`를 참조하지 않고 `IEditorHost`에만 의존함. 의존 부품은 생성자로 주입됨 | 확인(`grep MainWindow src/Editing` → 0건) |
| T2-4 | OCP: 명령 실행 | `Run()`은 명령 표 조회만 하고, 명령 추가는 표에 한 항목을 넣는 것으로 끝남 | 확인(코드) |
| T2-5 | 렌더러 분리 | 도형 기하(`ShapeGeometry`), 색 변환(`ColorMath`), XML 도우미(`X`), `TextPanel`, `ShapeHit`이 각자의 파일에 있음 | 확인(코드) |
| T2-6 | 동작 보존 | 리팩토링 전 기준선 269건이 모두 통과. 이번에 보강한 `loc:` 검사 2건(소스 탐색 확인, 갤러리 도형 이름)을 더해 271건 PASS, FAIL 0건 | 자동 전체 |

### T3. 문서 모델: 열기, 저장, 실행 취소

| ID | 테스트 내용 | 충족 조건 | 방법 |
|---|---|---|---|
| T3-1 | 열기와 렌더링 | 모든 슬라이드가 예외 없이 그려지고 PNG로 저장됨 | 자동 `slide n:` |
| T3-2 | 텍스트 편집 저장 | 편집한 텍스트·글꼴 크기가 저장 후 다시 열어도 유지됨 | 자동 `edited text saved`, `font size saved` |
| T3-3 | 저장과 변경 표시 | 저장하면 변경 표시(Dirty)가 지워짐 | 자동 `save clears dirty` |

| T3-5 | OOXML 유효성 | 편집한 슬라이드의 검증 오류 0건, 다시 열면 모든 도형이 그려짐 | 자동 `file:` |
